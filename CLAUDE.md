# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

pnpm monorepo, Node 26+ (`engines`), pnpm version from `packageManager`.

```bash
pnpm dev:server        # apps/server on :8787, proxy allows localhost targets, restarts on change
pnpm dev               # apps/web (Vite) on :5173, /proxy forwarded to :8787
pnpm check             # typecheck + lint + test + build: the exact CI entry point, run before pushing
pnpm --filter web test # or: --filter server
node --test apps/web/src/lib/typesense/schema-diff.test.ts   # a single test file
docker compose up -d   # demo Typesense on :8108, API key `demo-key`
pnpm seed              # (re)creates `demo_books`, 3,000 deterministic documents
```

Lint is `oxlint`; it currently reports 10 warnings in generated `components/ui` files and stores. Keep it at that count. There is no formatter config: match the surrounding style (no semicolons, single quotes, 2 spaces, long lines are fine).

## Architecture

**apps/server** is a dependency-free `node:http` server that runs its TypeScript sources directly (no build). It serves the built web app (`STATIC_DIR`, optional `BASE_PATH`, optional Basic Auth) and a CORS proxy at `/proxy/*`. The proxy forwards to the origin in the `X-Typesense-Target` header, only if it matches `PROXY_ALLOWED_TARGETS` (`allowlist.ts`); it forwards any HTTP method but only the API key, `Content-Type` and `Accept` headers, and streams bodies.

**apps/web** is a React 19 SPA (Vite, Tailwind v4, shadcn on Base UI, TanStack Router + Query, Zustand, i18next).

- **Transport**: `lib/typesense/client.ts` builds one `TypesenseClient` per connection. A connection's `transport` is `direct` (browser → Typesense, needs CORS) or `proxy` (→ `apps/server`); `native` is chosen automatically inside the planned Tauri shell. Network failures become `TypesenseError` with `status: 0`; `useErrorMessage` (`hooks/use-typesense.ts`) turns errors into UI text. All endpoints live in `lib/typesense/api.ts`; there is no Typesense SDK dependency, on purpose.
- **Admin keys only**: a connection is only usable with a key that may call `GET /keys`. Typesense answers 401 for unknown keys and for keys without that permission alike (`isKeyRejected`). Keys live in `stores/connections.ts`: sessionStorage by default, localStorage only with "remember".
- **Routing**: hash history (`router.tsx`), so the build works under any sub-path and in the desktop shell. Everything below `/c/$connectionId` renders inside `pages/connection-layout.tsx`, which provides `useActiveConnection()` (connection + client). The search page keeps its whole state in URL search params, validated by `parseDocumentSearch` (`lib/typesense/search.ts`).
- **Query keys** start with the connection id: `[connectionId, 'collections']`, `[connectionId, 'collections', name]`, `[connectionId, 'keys']`. Invalidating `[connectionId, 'collections']` refreshes the list, the schema page and the search page together.
- **Typesense logic stays out of components**: schema-derived field lists (`lib/typesense/search.ts`) and the schema diff (`lib/typesense/schema-diff.ts`) are pure modules. Pure modules that have tests import types with an explicit `.ts` extension, because the tests run under Node's own module rules (test files are type-checked by `tsconfig.node.json`, excluded from `tsconfig.app.json`).
- **CodeMirror** is only loaded through `components/lazy-json-editor.tsx` (own chunk, textarea fallback if the chunk fails to load). Do not import `components/json-editor.tsx` directly.
- **i18n**: `i18n/locales/en.ts` defines the `Messages` type; `de.ts` must provide every key, so a missing translation is a type error.

### UI conventions

- `components/ui/*` is generated by shadcn (`components.json`, style `base-nova`). It is built on Base UI, not Radix: compose with the `render` prop instead of `asChild`.
- Base UI comboboxes clear their selection on Escape; wrap `onValueChange` with `isEscapeClear` (`lib/combobox.ts`) so Escape only closes the list.
- Links that look like buttons use `<Link className={buttonVariants(...)}>`, not `<Button render={<Link/>}>` (that sets `role="button"`). Sidebar links whose path is a prefix of another route need `activeOptions={{ exact: true }}`.
- Search highlights use control characters (`HIGHLIGHT_START`/`HIGHLIGHT_END`) and are rendered as React nodes, never as HTML.

## Typesense behavior worth knowing

Verified against Typesense 30; details in `docs/designs/schema-editing.md`.

- `PATCH /collections/:name` accepts only `fields`, `metadata` and `synonym_sets`, and applies all of a request or none. A field change is `{name, drop: true}` followed by the new definition; it re-indexes that field and blocks writes meanwhile.
- Dropping or changing the field named in `default_sorting_field` silently clears that setting for good.
- For wildcard searches, facet `stats.total_values` is capped at `max_facet_values`; ask for one value more to know whether there are more (`FACET_VALUES`).
- Unknown key actions are accepted without error, and the bootstrap key never appears in `GET /keys`.

## Workflow

- Larger features get a design doc in `docs/designs/` before implementation.
- CI only runs for pushes to `main` and PRs into `main`. For stacked PRs, GitHub does not retarget a child PR when its base is merged unless the base branch is deleted, so check that every commit really reached `main`. A PR retargeted to `main` needs a close and reopen to start CI.
